## TCP/IP

Transmission of data from one device to another over a network is handled by the Internet Protocol Suite, which includes the link layer, Internet Protocol (IP) layer, Transmission Control Protocol (TCP) layer, and application layer.

The link layer handles transmitting data within a local network, ie. from a laptop to a home router via ethernet or Wi-Fi or vice-versa. Data in this layer is wrapped up in ethernet or Wi-Fi frames, and contains the source and destination MAC addresses to hop between network devices.

The IP layer wraps data in the form of packets. The two primary focuses of this layer are fragmenting the data into manageable chunks and routing each packet to their correct destination. The routing is handled by attaching a logical address of the destination device (IP address) to each packet, which routers will use to decide how the data will traverse across multiple networks.

The TCP layer is the main transport layer which ensures that data is transferred reliably across networks. The TCP protocol makes sure that all packets arrive successfully and in the correct order, and handles retransmission of lost packets. To achieve this, each packet has a segment number which identifies the order of where it belongs in the datagram. The IP handler verifies received packets and presents them to the TCP handler, which will pass the packets in correct order to the application layer. If any packet in the sequence is missing, TCP will hold the rest in buffer until the missing packet arrives. The TCP handler will acknowledge all received packets, and the server will retransmit any missing packets before continuing to send the rest of the data. 

TCP is a connection-oriented protocol, and it requires a three-way handshake (SYN SYN ACK, OR SYN SYN-ACK ACK) between the client and server to establish connection before beginning to transfer data. The amount of back-and-forth communication to ensure reliable data transfer adds a significant amount of latency time to data transfer. Aside from TCP, this layer has another possible protocol called the User Datagram Protocol (UDP). UDP does not require an established connection and is useful when speed is prioritized over reliability with tolerance for some data loss (ie. real-time applications involving streaming video/audio, or online multiplayer games). Developers will often use UDP and implement their own protocol on top of it so that they have more control over how to handle the received the data.

The application layer is the top-most layer which defines protocols such as HTTP, SMTP, FTP, and DNS. These protocols handle the different needs of software communication and how to format the data.
